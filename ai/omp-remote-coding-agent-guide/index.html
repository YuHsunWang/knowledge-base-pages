    Oh My Pi（OMP）遠端 Coding Agent 完整設定與使用指南¶

    摘要¶

    私人筆電執行 OMP，其他電腦與手機透過 Collab 在瀏覽器控制同一工作階段；Shell、檔案修改與測試仍在筆電執行。

    資料基準：2026-09。執行前請以 omp --help、omp config list 與 omp models 核對目前版本支援的選項。

    1. 使用情境¶

    這套設定的分工：

    • OMP、程式碼與 Docker、Python、Node.js、資料庫等服務留在私人筆電。
    • 其他電腦使用 Chrome / Edge 等瀏覽器，無須 Remote Desktop。
    • 手機透過 Safari / Chrome 控制同一個 OMP session。

    整體架構¶

    圖 1：OMP 遠端控制整體架構

    其他電腦與手機只負責控制 OMP：

    其他電腦 / 手機
    ↓
OMP Collab
    ↓
私人筆電上的 OMP
    ↓
程式碼 / Bash / Docker / DB / Git

    所在網路若允許瀏覽器連線至 OMP Collab 所需的 HTTPS / WebSocket，便可透過瀏覽器操作。

    IT Policy

    在他人管理的電腦或網路上使用時，必須遵守該環境的 IT、安全與資料處理政策。不應使用 OMP Collab 來規避明確禁止的外部工具、資料外傳限制或安全控制。

    2. 安裝 OMP¶

    macOS / Linux¶

    curl -fsSL https://omp.sh/install | sh

    或使用 Homebrew：

    brew install can1357/tap/omp

    安裝完成：

    omp --version

    查看 CLI：

    omp --help

    Windows¶

    PowerShell：

    irm https://omp.sh/install.ps1 | iex

    3. 第一次初始化¶

    執行：

    omp setup

    OMP 主要的全域設定位置通常是：

    ~/.omp/agent/config.yml

    自訂模型 / Provider：

    ~/.omp/agent/models.yml

    專案設定可放：

    your-project/
└── .omp/
    └── config.yml

    查看設定：

    omp config list

    查單一設定：

    omp config get tools.approvalMode

    查看目前 Agent 設定路徑：

    omp config path

    4. Provider 登入¶

    最簡單：

    omp login

    再從選單選擇 Provider。

    例如：

    omp login anthropic

    或：

    omp login openai

    實際可用 Provider 請以：

    omp login

    目前版本列出的項目為準。

    5. 查看可用模型¶

    列出模型：

    omp models

    尋找 Claude：

    omp models find claude

    尋找 GPT：

    omp models find gpt

    尋找 Gemini：

    omp models find gemini

    使用 OMP 時，不建議直接照抄網路文章中的模型名稱。

    應先執行：

    omp models

    再以目前帳號與 Provider 實際可用的模型名稱設定。

    6. OMP 的 Model Roles¶

    OMP 可按工作類型切換模型。常見角色：

    Role 用途
    default 日常主要 Coding
    smol 快速、低成本工作
    slow 深度推理、疑難除錯
    plan 規劃與架構分析
    vision 圖片 / 視覺相關
    advisor 第二模型 Review
    task Subagent 工作
    designer 設計相關

    範例：

    modelRoles:
  default: anthropic/claude-sonnet-4-5
  smol: openai/gpt-4.1-mini
  slow: anthropic/claude-opus-4-5:high

    上述模型名稱僅示範設定格式；實際名稱請以 omp models 的清單為準。

    7. 模型切換¶

    進入 OMP：

    omp

    在互動介面輸入：

    /model

    也可在啟動時指定：

    omp --model <provider>/<model>

    或：

    omp --model slow

    或使用 Role 參照寫法：

    omp --model @slow

    Role Cycle¶

    設定：

    cycleOrder:
  - smol
  - default
  - slow

    設定後可在這三個 Role 間切換。

    模型選擇策略¶

    圖 2：模型角色切換策略

    可依工作量選擇 Role：

    smol
→ 搜尋
→ 小改動
→ 低成本 subtask

default
→ 日常 Coding
→ Feature 開發
→ 一般 Debug

slow
→ Architecture
→ Difficult debugging
→ Security analysis

plan
→ 需求拆解
→ Implementation plan

    8. Thinking Level¶

    如果模型支援 reasoning：

    omp --thinking high

    常見等級：

    off
minimal
low
medium
high
xhigh

    是否真正支援取決於 Provider / Model。

    9. 基本使用¶

    進入專案：

    cd ~/Projects/my-project

    啟動：

    omp

    範例 Prompt：

    先閱讀整個專案架構。

不要修改任何檔案。

請說明：
1. frontend
2. backend
3. database
4. API
5. authentication

彼此之間的關係。

    Debug：

    找出 login API 為什麼偶爾會出現 500。

先：
1. 重現
2. 找 root cause
3. 分析影響範圍

在我確認之前不要修改程式。

    修改：

    執行剛才的修正。

完成後：
1. 跑相關 tests
2. 顯示失敗測試
3. 顯示 git diff summary
4. 不要 commit
5. 不要 push

    10. 建議的 Prompt 模板¶

    不要只輸入：

    fix bug

    推薦：

    分析這個 bug。

要求：

1. 先重現問題
2. 找 root cause
3. 在修改前先說明計畫
4. 列出可能受影響檔案
5. 修改後跑 tests
6. 檢查 regression
7. 最後輸出 git diff summary
8. 不要 push

    大型工作：

    orchestrate

完成 payment service refactor。

要求：

1. 分析現有 architecture
2. 建立 implementation plan
3. 拆成適合平行處理的工作
4. 實作
5. 執行相關測試
6. Review git diff
7. 不要 push

    11. Session 保存與繼續¶

    正常啟動：

    omp

    繼續最近 session：

    omp --continue

    或：

    omp -c

    從歷史 session 選：

    omp --resume

    指定 session：

    omp --resume <session-id>

    Fork：

    omp --fork <session>

    在私人筆電：

    cd ~/Projects/my-project
omp

    進入 OMP 後：

    /collab

    OMP 會顯示：

    Join from another terminal:
omp join "..."

Browser:
https://my.omp.sh/#...

    OMP 也會顯示 QR Code。

    13. 其他電腦使用¶

    其他電腦用瀏覽器開啟 Collab URL，無須安裝 OMP：

    https://my.omp.sh/#你的-session-key

    例如：

    幫我查看目前 git status。

先不要修改任何東西。

    實際流程：

    其他電腦 Browser
      ↓
OMP Collab
      ↓
私人筆電 OMP
      ↓
Git / Docker / Files / DB

    14. 手機使用¶

    手機 Safari / Chrome 打開同一個 Collab URL。

    或者：

    /collab

    後直接掃 QR Code。

    例如外出時：

    現在進度到哪？

    或：

    分析目前失敗的 test。

先不要修改 database migration。

    15. Collab 指令¶

    完整控制：

    /collab

    唯讀：

    /collab view

    狀態：

    /collab status

    停止：

    /collab stop

    Guest 離開：

    /leave

    查看 Active Hosts：

    omp collab list

    取得連結：

    omp collab link <instanceId>

    唯讀連結：

    omp collab link <instanceId> --view

    16. Collab URL 是敏感憑證¶

    Collab URL 是敏感憑證

    Full-control Collab URL 必須當成 Password。

    不要：

    • 貼到 Slack 公開頻道
    • 貼到 GitHub Issue
    • 放在公開 Notion
    • 放進 Repository
    • 寄到多人 Mailing List

    Full-control 使用者可能可以：

    • 發送 Prompt
    • Interrupt Agent
    • 讓 Host 執行 Tool
    • 間接操作你的開發環境

    需要分享畫面時，優先：

    /collab view

    17. 自動開啟 Collab¶

    設定 Full Control：

    omp config set collab.autoStart control

    唯讀：

    omp config set collab.autoStart view

    關閉：

    omp config set collab.autoStart off

    設定名稱：

    omp config set collab.displayName Shane-Laptop

    18. Host 筆電必須保持在線¶

    這套架構的必要條件：

    私人筆電
= 真正的 Agent Host

    因此：

    狀態 可否遠端工作
    筆電開機 + OMP 執行中 可以
    OMP 關閉 不行
    筆電睡眠 通常不行
    筆電斷網 不行
    筆電關機 不行

    因此應調整：

    • macOS / Windows Sleep
    • Lid close 行為
    • Network sleep
    • Power settings

    19. Approval Mode¶

    安全設定

    遠端使用尤其重要。請先確認工具核准模式，再開放遠端控制。

    常見模式：

    always-ask
write
yolo

    概念：

    Mode Read Write Shell / Exec
    always-ask 自動 問 問
    write 自動 自動 問
    yolo 自動 自動 自動

    遠端操作推薦先使用：

    omp config set tools.approvalMode write

    再視需要調整。

    更細設定¶

    tools:
  approvalMode: write
  approval:
    bash: prompt

    這樣：

    讀檔
→ 自動

寫檔
→ 自動

Shell
→ 要你確認

    20. 推薦 config.yml¶

    modelRoles:
  default: YOUR_MAIN_MODEL
  smol: YOUR_FAST_CHEAP_MODEL
  slow: YOUR_REASONING_MODEL
  plan: YOUR_PLANNING_MODEL

cycleOrder:
  - smol
  - default
  - slow

tools:
  approvalMode: write
  approval:
    bash: prompt

collab:
  autoStart: control
  relayUrl: wss://my.omp.sh
  displayName: Shane-Laptop

    位置：

    ~/.omp/agent/config.yml

    模型名稱請先：

    omp models

    再填入。

    21. AGENTS.md：讓 OMP 記住專案規則¶

    Repository：

    AGENTS.md

    範例：

    # Project Instructions

- Python 使用 uv
- 修改完成後執行 pytest
- 不要直接修改 production database
- 不要直接 push main
- Migration 必須先取得使用者確認
- TypeScript 使用 strict mode
- Commit message 使用 Conventional Commits

    這樣就不需要每次重新提醒。

    22. Project-specific Config¶

    例如工作專案：

    ~/Projects/work/.omp/config.yml

    可以比較保守：

    tools:
  approvalMode: always-ask

    私人專案：

    ~/Projects/personal/.omp/config.yml

    可以：

    tools:
  approvalMode: write

    23. 自訂 OpenAI-compatible Provider¶

    檔案：

    ~/.omp/agent/models.yml

    範例：

    providers:
  my-provider:
    baseUrl: https://api.example.com/v1
    api: openai-completions
    apiKey: MY_API_KEY
    models:
      - id: my-model
        name: My Model
        contextWindow: 128000
        maxTokens: 8192

    API Key 不要直接硬編碼。

    例如：

    export MY_API_KEY="..."

    然後：

    omp models my-provider

    24. API Key 安全¶

    API Key 安全

    API Key 請透過環境變數或 Provider 登入管理，不要提交至 Git。

    不要：

    apiKey: sk-xxxxxxxx

    然後 commit 進 Git。

    推薦：

    apiKey: OPENAI_API_KEY

    再設定：

    export OPENAI_API_KEY="..."

    或者使用：

    omp login

    25. Notification 的兩個層次¶

    OMP 介面通知與手機推播分開設定：

    A. OMP UI / Terminal Notification¶

    例如 extension 可以：

    ctx.ui.notify("Task complete", "info");

    這主要作用於 OMP UI / Host terminal。

    B. 真正的手機 Push Notification¶

    如果想：

    OMP 完成工作
↓
iPhone / Android 鎖屏通知

    應另外接：

    • ntfy
    • Telegram Bot
    • Pushover
    • Discord Webhook
    • Slack Webhook

    27. OMP Extension¶

    Extension 可以放：

    ~/.omp/agent/extensions/

    例如：

    ~/.omp/agent/extensions/mobile-notify.ts

    最小 Extension：

    import type { ExtensionAPI } from "@oh-my-pi/pi-coding-agent";

export default function (pi: ExtensionAPI) {
  pi.on("session_start", async (_event, ctx) => {
    ctx.ui.notify("OMP extension loaded", "info");
  });
}

    OMP Extension 可以註冊：

    • Session event
    • Agent event
    • Slash command
    • Tool
    • UI notification

    28. ntfy 通知概念¶

    例如：

    curl \
  -d "OMP task completed" \
  https://ntfy.sh/YOUR_PRIVATE_TOPIC

    Topic 名稱請視為 Secret。

    不要放進公開 Repository。

    可以使用環境變數：

    export OMP_NTFY_TOPIC="your-private-topic"

    Extension 再讀：

    const topic = process.env.OMP_NTFY_TOPIC;

    29. 手機通知 Extension 範例骨架¶

    以下是概念範例，實際事件名稱與 API 應依目前 OMP Extension 文件核對：

    import type { ExtensionAPI } from "@oh-my-pi/pi-coding-agent";

export default function mobileNotify(pi: ExtensionAPI) {
  pi.on("agent_end", async (_event, ctx) => {
    const topic = process.env.OMP_NTFY_TOPIC;

    if (!topic) {
      ctx.ui.notify("OMP_NTFY_TOPIC not configured", "warning");
      return;
    }

    try {
      await fetch(`https://ntfy.sh/${topic}`, {
        method: "POST",
        body: "OMP task completed",
      });

      ctx.ui.notify("Mobile notification sent", "info");
    } catch (error) {
      ctx.ui.notify("Failed to send mobile notification", "error");
    }
  });
}

    可逐步加入：

    • Error notification
    • Waiting-for-input notification
    • Project name
    • Git branch
    • Task summary
    • Session link

    36. 推薦的 AGENTS.md¶

    # Project Agent Rules

## General

- Before modifying code, inspect the relevant implementation first.
- For large changes, present a plan before editing.
- Do not push code unless explicitly requested.
- Do not deploy production unless explicitly requested.

## Testing

- Run relevant unit tests after code changes.
- Run lint/typecheck when applicable.
- If tests fail, report the failure before making unrelated changes.

## Database

- Never modify production database.
- Ask before generating or applying migrations.
- Never run destructive SQL without explicit approval.

## Git

- Never force-push.
- Never push directly to main.
- Show git diff summary before commit.

## Security

- Never print secrets.
- Never commit .env files.
- Never expose API keys or tokens.
