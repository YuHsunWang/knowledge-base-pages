    Sepia：從敘事結構下手的去 AI 味 Skill¶

    整理自 Nanako0129/sepia 0.8.0 的 README 與 skill 原檔，2026-10-03。

    ⚠️ 文中的研究數字都引自 repo 的 research/ 與 references/，本庫沒有獨立重跑過。

    2026-09-06 改求職履歷。104 自傳已經跑過我自己的 anti-ai-writing，PDF 版的個人簡介卻漏掉沒檢查。補跑 Sepia 之後，它抓出一組三段排比，還有經歷句尾連續四次的「讓…」。

    一句話¶

    Sepia 是一個去 AI 味的 Agent Skill。它不只換字：小說先查敘事架構，專業文件先看是哪一種文件，再決定套哪套規則。

    換字為什麼不夠¶

    多數 humanizer 只改用詞和句法：刪掉「此外」、拆掉排比、換掉陳腔濫調。

    Sepia 引用的 StoryScope（arXiv:2604.03136，61,608 篇故事）量到一件事：只看敘事結構特徵的分類器，就能用 93.2% macro-F1 認出 AI 寫的小說。人類編輯把字句改過一輪之後，偵測率也只從 95.5% 掉到 93.9%。

    也就是說，破綻大多不在字句。常見的幾種：

    • 敘事者把主題直接講出來
    • 情節單線，因果收得太整齊
    • 情緒只靠身體感受呈現
    • 沒有真實世界的人名、地名、作品
    • 結局一定是主角成長、學會接納

    字句換得再乾淨，架構沒動，一樣看得出來。

    怎麼運作¶

    先分路¶

    文字類型 走哪條路
    小說、故事、敘事散文 敘事架構 → 篇章推進 → 字句風格，三個 pass 由深到淺
    發版說明、公告 使用者影響擺前面、每項宣稱附佐證
    PR / issue 回覆 先給答案、引用 file:line、不反射性稱讚
    事故檢討 對人不究責，對機制追到底；行動項目要有負責人
    工單 標題寫結果，驗收條件要能測
    技術文章 從問題切入、留一條真的走過的死路、給一個明確判斷

    專業文件不走敘事那套，但最後都要過一次字句掃描和句長節奏檢查。

    四種操作¶

    操作 Claude Code 指令 做什麼
    write /sepia-write 寫新的。先讀規則再動筆
    review /sepia-review 只列問題，不改
    refactor /sepia-refactor 原文上小改
    recreate /sepia-recreate 抽出事實清單，整篇重寫

    另外有 /sepia-hemingway，用內建的海明威聲音寫或改小說。總入口是 /sepia。

    refactor 一定分兩段：先列完整問題清單，再一條一條修。理由寫在 SKILL.md 裡：沒有清單就直接改寫，專家偵測器反而更容易看出 AI 指紋。

    修的時候偏向刪和換，少加字。它引的人類編輯比例是 74% 替換、18% 刪除、8% 新增。

    校準：別矯枉過正¶

    這條我覺得最有價值。把每個 AI 特徵都反過來做，會變成另一種指紋。

    人類的數值多落在中間。所以 Sepia 每篇只挑 3–5 個手法，其餘留白。專業文件也一樣，正式場合維持正式語氣，硬裝口語騙不了懂行的讀者。

    中文有專門的校準檔¶

    中文文本會多載入 references/languages/zh.md。數字來自 HC3-Chinese 語料（2023，GPT-3.5 時代的 ChatGPT，簡體中文問答，人類與 AI 各 6,586 篇）：

    特徵 人類 ChatGPT
    句長標準差（詞） 9.248 6.729
    語氣詞密度 0.016 0.003
    連詞密度 0.013 0.036
    單音節詞比例 0.483 0.379

    翻成白話：AI 的句子長度太平均，連詞用太多，語氣詞太少，愛用「進行討論」「加以說明」這種雙音節墊字。

    它也列了不算訊號的東西：標點密度、段落數、句子長短本身。很多人以為 AI 愛寫一大坨，這份語料裡 ChatGPT 反而分了比較多段。

    「不是…而是…」、到處三段排比、段首「其實」這幾條，檔案標成台灣編輯的經驗談，沒有語料數字。

    限制它自己寫得很清楚：一份語料、一個模型世代、簡體問答。2024 年以後的模型在中文上沒有量測，台灣繁中也沒有學術研究。數字只能當方向看。

    我用過一次¶

    開頭那次履歷，跑的是 refactor（專業路線＋中文校準）。抓到的兩個問題，anti-ai-writing 理論上也抓得到，那次漏掉是因為根本沒對 PDF 跑。只有一次使用，談不上評測。

    跟 anti-ai-writing 怎麼分¶

    兩者在字句層重疊。Sepia 多出來的是：

    • 按文件類型分規則（PR 回覆跟事故檢討不同套）
    • 小說的敘事架構檢查
    • 有研究出處的中文校準

    我的寫作 pipeline 第 4 步目前還是 anti-ai-writing。要不要換成 Sepia，還沒決定。

    安裝¶

    claude plugin marketplace add Nanako0129/sepia
claude plugin install sepia@sepia --scope user

    其他 agent 可以用 Skills CLI：npx skills add Nanako0129/sepia -g（-g 才是裝到使用者層級）。Codex、Grok Build、Antigravity 也有原生 plugin，指令見 repo README。
